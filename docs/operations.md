# 部署、发布与恢复

Velin 当前按面向公众销售、保留邮箱注册的单用户账号产品维护。支持 Windows 11 x64 与 macOS 13+ ARM64。组织、租户、团队管理员和收费账单不属于当前实现。

## 服务部署

使用 Node.js 24、PostgreSQL 18 和项目的 Node 启动入口。部署包保留 `apps/web/src`、`scripts`、`migrations`、生产依赖及 `.next`；文档处理使用独立 TS 子进程，因此 `tsx` 属于生产依赖。不能仅复制 `.next` 或绕过入口执行 `next start`。

先部署兼容的新迁移，再启动 Web 和 OCR worker。推荐在维护窗口停止旧版本写入、备份数据库、执行 `pnpm db:migrate`，然后运行 `pnpm build` 和 `pnpm start`。Web 启动时核实迁移清单，缺失迁移会拒绝监听。对数据有破坏性的回退不能只运行 down SQL，必须先恢复备份并匹配应用版本。

反向代理终止 HTTPS，配置真实 `APP_URL`、`PASSKEY_RP_ID` 和代理 IP。覆盖或正确追加 `X-Forwarded-For`，不信任用户注入的地址头；保留 SSE 流、关闭聊天路由缓冲，并把代理读超时设为高于生成时限。正文限制仍由应用独立核实。生产需要真实 SMTP、OAuth 和模型凭据；SMTP 使用隐式 TLS 或强制 STARTTLS，不能降级为明文认证。

应用在接收请求体时同时执行大小限制与 60 秒总读取时限，取消和超时分别返回稳定错误代码；不等待异常流的取消回调。碎片正文按固定容量缓冲，避免大量微小片段积累无界对象。代理还需配置连接数、请求头与上传速率预算，应用正文时限不代替入口连接保护。

Web 和 OCR 使用各自的受限服务账号及进程/容器资源预算。Office、图片、PDF 解析子进程移除了数据库、模型、SMTP 和认证凭据；V8 堆限制、超时、解压/像素预算不能代替操作系统对总 RSS、CPU 和进程数的限制。解析进程并非操作系统沙箱。按部署平台配置总内存、CPU、文件系统和外连白名单，并为临时目录设置容量限制。PostgreSQL 连接池是每个进程的预算，增加实例数时一并核算总连接数。

`/api/health` 检查 Web 与数据库连接。`/api/ready` 另检查已应用迁移及 OCR、清理任务最近的心跳；后台心跳有最长 120 秒的失效窗口。负载均衡使用 ready，进程探活按实际平台配置。清理随独立 OCR worker 运行，不依赖再次上传文件。

## 账号停用

管理员使用数据库运维权限执行以下命令；没有公开管理员 HTTP 入口。先核实用户标识与目标数据库，不把凭据写进命令行历史。

```bash
pnpm --filter @velin/web account:access suspend USER_ID
pnpm --filter @velin/web account:access restore USER_ID
```

停用事务清除全部设备会话和未消费操作授权。登录仍由认证库验证；库 Hook 提供明确拒绝，数据库触发器与用户行锁阻止停用期间补写迟到会话。恢复后需要重新登录。已经发起的上游处理受原有取消和超时预算约束，停用不等于向第三方撤回已发送的内容。

## 数据流与保留

消息文字、预算内的历史、提取的附件文字和所选原图会发送给 DeepSeek；标题生成也使用首条消息的一部分。原图选择先在数据库元数据层完成，再读取受预算约束的原图。切换到不支持图片的模型时，包含图片的上下文会被服务端拒绝。

聊天历史保留到用户删除对话或账号被删除。删除对话级联删除消息、附件、待发送附件及逐页识别数据；同账号仍有其他附件引用的 OCR 缓存可以继续复用，最后一个引用删除后同步清除。跨附件 OCR 缓存另有 24 小时 TTL 和行数上限。未发送附件在 24 小时后由独立任务回收，正常运行时清理粒度约为一分钟。已发送附件保留用于历史展示，不按暂存期限误删。

本地文字草稿按账号和对话隔离，在最后写入后保留 24 小时，最多保留最近 100 份。启动和定时清理删除过期数据；应用未运行时，下次启动执行清理。草稿不是凭据加密存储，终端应使用系统磁盘加密与适当的设备访问控制。会话凭据使用系统安全存储；不可用或弱后端只保留内存会话。

应用日志不记录消息、附件原文、Cookie、令牌和密码。HTTP 响应返回 `X-Request-ID`，关联到状态、耗时和错误分类；生成请求 ID、OCR 附件/generation/attempt 标识由其所属表维护。日志平台按运营要求设置保留期限和告警，不能把任意第三方错误对象展开记录。

数据库删除不会追溯清除已经发送给供应商的数据，也不会立即抹去 WAL、磁盘空闲页或历史备份。上线前运营方需确认供应商协议、允许的数据类别、备份保留和用户请求处理流程，并发布包含真实运营主体与联系渠道的数据说明。开发仓库不虚构供应商保留或训练承诺。

## 额度与故障排查

请求按账号和全局 UTC 日计数桶原子预留，分钟窗口与活动请求按用户索引查询。重放 requestId 不重复占用额度。日额度统计已经接受的尝试，后续模型失败或取消不退回；它是资源保护策略，不是收费账单。主回复和标题分别保存模型与已知 token 用量，缺失 usage 使用 null 表示未知，不能当作零成本。不同模型的货币成本须结合供应商实际账单和价格版本核对。

预留先取得当前用户行锁，再通过带上限条件的原子 upsert 预留全局日桶；等待某个账号时不持有全局锁。全局桶仍会在短事务内串行更新，不能把移除全局 advisory lock 解释为无限扩展能力。跨账号 requestId 竞争失败时回滚本次计数；拒绝新请求也会提交已完成的过期请求清理。

回复正文终态与请求用量在同一事务提交，随后才发送完成事件。`incomplete` 表示长度限制、过滤或上游未正常结束，界面保留区别于完整成功的状态。保存失败只返回失败反馈；重开或刷新从持久化数据恢复。慢数据库 checkpoint 合并到最新快照，暂停读取的流客户端有背压等待上限。

过期的活动请求与流式消息由预留入口或维护任务原子标为失败；旧执行无权覆盖已关闭的消息。排查持续显示生成中的回复时，同时检查请求租约、维护心跳和数据库锁等待，避免只改用量状态而遗留可写消息。

模型生成（含按需上下文整理）限时 420 秒，桌面传输限时 450 秒，为最终数据库提交保留余量；SSE 闲置时每 15 秒发送注释心跳。正文与推理分别限制为 256 Ki 个 UTF-16 码元，单次增量最多 8 Ki，避免 JSON 转义后超出客户端 128 Ki 的 SSE 解析缓冲区；达到输出上限保留不完整状态。取消或失败时已经生成的推理仍保存，迟到的标题必须绑定仍存在的生成请求，不能覆盖编辑重发后的标题。

关注保存失败率、请求耗时、HTTP 429/5xx、上游未知用量、连接池等待、OCR 与 chat-context-maintenance 队列积压、失败任务及清理心跳。就绪失败先检查迁移和 worker；回复保存失败按请求 ID 定位数据库超时/锁等待，不以重试模型请求代替恢复数据库。OCR 系统故障由队列有限重试；generation/attempt fencing 防止旧执行覆盖新任务。不要在原任务仍活动时人工把它复制为另一份任务。

`chat.context_stage` 按 generationId、purpose、outcome 记录摘要、历史与文件准备耗时；`chat.first_output` 分别记录首段正文和首段推理成功写入流的耗时，包含上下文准备及流背压等待。两者不记录对话内容。按模型、阶段与结果聚合分位数，区分模型生成、上下文和传输延迟；本地替身测试的耗时不能作为生产 SLA。

## 备份与恢复

上线前为 PostgreSQL 启用加密备份、连续 WAL/PITR 和访问审计，明确 RPO、RTO 与保留期限。备份须存放到与数据库故障域不同的位置，并保护数据库外的认证密钥及部署配置；没有原密钥时，恢复的加密认证数据不一定可用。

定期将备份恢复到隔离数据库，核对迁移版本、用户/会话关系、聊天序号、附件外键和队列状态，然后运行项目的集成测试及真实页面验收。演练不得复用生产 SMTP、OAuth 或模型凭据。确认备份的到期删除遵循对用户公布的保留规则。恢复旧备份可能恢复已撤销会话，正式切回前应按事故范围撤销会话并重新登录；不能以一次 `pg_restore` 命令成功认定业务已恢复。

## 桌面包与更新

构建阶段设置 `VELIN_API_SERVER_URL`，它会随 Main 打包，正式应用不依赖 shell 环境变量。打包只接受不带凭据、查询和路径的 HTTPS 服务来源。开发运行允许明确的回环 HTTP。

```bash
VELIN_API_SERVER_URL=https://YOUR_SERVICE_HOST pnpm --filter @velin/desktop package:dir
VELIN_API_SERVER_URL=https://YOUR_SERVICE_HOST VELIN_UPDATE_URL=https://YOUR_UPDATE_HOST/stable VELIN_WINDOWS_PUBLISHER='YOUR_CERTIFICATE_PUBLISHER' pnpm --filter @velin/desktop package:release
```

在目标平台构建：macOS ARM 生成 DMG/ZIP，Windows x64 生成 NSIS。`package:dir` 仅供开发烟雾测试；正式 release 强制平台签名，macOS 还要求 `APPLE_API_KEY`、`APPLE_API_KEY_ID`、`APPLE_API_ISSUER` 公证配置。证书等签名配置遵循 electron-builder 的公开接口，进入 CI 密钥存储，不能写进源码。发布命令只生成产物，始终 `publish: never`；上传托管和对外发布需要单独执行。

“检查更新”使用随包配置的 HTTPS 更新源；由维护中的 updater 验证下载校验和及平台代码签名，Windows 绑定发布者名称。用户决定下载和重启，不自动在退出时安装或降级。当前稳定依赖线不声明具备 v27 预览版的签名 manifest 功能；保护更新托管写入权限，不能以 sha512 校验和代替发布者签名。安装、冷启动深链、多实例、证书轮换、断网和更新失败都应在真实 Windows 11 与 macOS ARM 安装环境验收。[稳定版更新机制](https://www.electron.build/v26/docs/features/auto-update/)

## 持续验证

`pnpm --filter @velin/desktop test:native` 在真实 Electron 中使用隔离的临时 profile，验证剪贴板与设备权限、外部导航拦截、刷新与 Renderer 崩溃的任务清理。它不访问真实账号或剪贴板内容，已纳入 Windows/macOS 桌面矩阵；Linux 无显示环境的普通服务端套件不替代此项。

`.github/workflows/verify.yml` 使用最小只读权限、固定 Action commit 和隔离 PostgreSQL。服务端门禁执行 lint、类型、生产依赖审计、真实认证/聊天/OCR、300 页负载、SSR/CSP 与构建；`pnpm test:ci` 缺少隔离数据库时直接失败。OCR 套件串行执行，避免不同 worker 抢走其他测试的任务。桌面矩阵生成 Windows、macOS ARM 的未签名测试目录，产物保留七天；这些产物不能直接作为正式发布包。

CI 配置进入仓库不等于已经在远端执行。真实 SMTP/TLS、Google 账号回跳、设备通行密钥、生产代理、签名公证和安装升级仍需要对应环境与凭据。发布前记录实际证据，不能用 fixture 或编译通过代替验收。

记忆整理与 OCR worker 在同一独立进程运行，队列各自消费。辅助整理也会调用 Responses，已知用量累加到 chat_request_usage.context_input_tokens / context_output_tokens。关闭记忆停止使用和新提取，删除主题和清空的水位阻止旧任务重建条目；原聊天单独保留。详见 [对话与记忆](conversation-memory.md)。

原文索引由数据库触发器与消息事务同步维护；必须完成仓库全部迁移再启动新代码。跨对话检索仅访问当前账号的活动原文，关闭历史参考、清空水位及来源依赖在候选读取和生成前再次验证。查询扩展、证据重排和格式修复会增加辅助调用；应分别监测 `chat.recall_degraded`、`chat.auxiliary_format_retry`、上下文 token 用量与首段输出耗时。付费质量回归使用显式的 `pnpm eval:memory` 和隔离测试库，不对生产聊天做自动评测，也不把合成场景的结果当成生产 SLA。
