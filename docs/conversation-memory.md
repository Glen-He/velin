# 对话与记忆

模型调用统一通过 DeepSeek 的 `POST /responses`，主回复使用语义 SSE 事件，标题和辅助整理使用普通响应。参考 [Responses 指南](https://api-docs.deepseek.com/guides/responses_api/) 与 [接口文档](https://api-docs.deepseek.com/api/create-response/)。DeepSeek 不支持服务端会话持久化、`previous_response_id`、自动 compaction 或 `file_search`；不把静默忽略的参数当成已实现功能。请求显式使用 `store: false`，身份字段使用内部用户标识的 SHA-256 摘要，避免向上游传邮箱等身份信息。

## 上下文

消息序号在数据库中始终按 bigint 比较与排序，传输时才使用字符串。查询必须明确引用数字列，不能让 `sequence::text` 的结果别名参与排序；近期选择、摘要批次和后台整理共同遵守此约束。跨位数边界及超过 JavaScript 安全整数范围的回归用于防止时间顺序倒置。

PostgreSQL 保存原始消息。近期上下文按完整用户轮次选择，不能以孤立的助手回复开头；停止、失败和未完整完成的回复带明确标记，不作为已核实结论。先查询最多 64 条候选，再按 48000 的保守 token 上界选择轮次；更早的全部活动消息按序整理为滚动摘要。超长单条逐段处理，整条完成后才推进摘要水位。UTF-8 字节数加消息开销用于保守上界，并非精确 tokenizer；当前总输入上界 262144，图片另计每张 16384，均为应用预算，低于所支持模型的上下文窗口。

摘要保留目标、明确约束、更正、关键数字、决策、未完成事项和消息 ID，最多 10000 字符。摘要失败阻止本轮生成，不能静默丢弃历史。后台任务预先整理；发送时按需补齐。摘要写入绑定对话修订号和递增消息水位，编辑或恢复版本使旧任务失效。

按需摘要与历史召回独立执行，并行准备；任一步失败或请求取消，会取消并等待另一项结束，再退出本轮准备。文件检索复用召回阶段产生的查询，保持真实依赖顺序。准备完成后仍在事务中复核账号、对话修订、记忆水位与来源，不能因并行省略一致性校验。

原文索引由 PostgreSQL 触发器在消息写入事务中维护：只索引活动分支的完整终态消息，流式 checkpoint 不重复建索引；编辑、停用、恢复和删除不会留下可召回的旧版本。中文二元词项与英文标识符经过 NFKC 规范化，分块保留重叠，GIN 支持词项交集查询。候选按消息和会话限额，防止一个长回复或大量重复聊天挤掉其他来源。

发送时用近期问答和当前问题生成最多三条语义改写查询，保留原始查询，补充本地日期范围通道，再用 RRF 合并名次。查询模型不负责决定历史是否存在，也不能否决原始查询；无需明确说“以前”，个性化问题也可找到相关背景。纯问候直接跳过检索。候选经模型按相关性、时间、更正和说话者筛选，输出只能引用已存在的候选及连续原文；服务端拒绝不存在的 ID 和改写过的证据。随后补充同轮用户消息与相邻片段，保留问答关系。当前采用词项召回加模型查询改写、证据重排，没有部署稠密向量索引，也不将它称为向量检索。

Main 在请求中附带系统时区，服务端独立校验 IANA 时区，按当地日期理解“昨天”等相对时间；日期过滤仅用于额外召回，模型误判日期不会排除原始查询。来源同时保留创建、更新时间与角色，避免把旧计划、后续更正和助手建议混为一谈。用户消息编辑后的记忆排序使用实际更新时间，并保留数据库的微秒精度。

查询改写和证据重排各有独立时限，格式输出使用供应商结构化格式并经 Zod 再校验；格式不符只重试一次，共用原有取消和超时预算，不自动重试有副作用的写入。仍不可用时降级到原始查询直接命中的片段，回复元数据及界面明确标记检索不完整。取消必须退出，不能作为降级继续生成。所有辅助调用的已知用量计入原请求；日志不记录问题、来源正文或模型原始错误。

回复存储本轮历史来源、消息标识、日期与原文，界面可展开核对。正文按 `[往事N]` 标记依据；证据不足时不把“未召回”表述为“用户从未说过”。来源保存数量有界，桌面 SSE 帧上限按历史和文件同时出现、最坏 JSON 转义验证。

原文、摘要、个人记忆与文件资料明确区分；系统提示要求把引用资料视为待分析数据，当前用户明确更正优先。提示词约束不能保证模型绝不受恶意文件影响，应用不因此授予模型任何文件执行、网络或凭据权限。

## 文件

文件按页切分并建立 PostgreSQL 索引，索引内容与完成标记在同一事务提交。后续追问仍检索同一活动对话中的文件，不依赖再次上传。短资料在预算内提供全文；长资料复用查询改写词项，按相关度、页码或尾部请求召回，候选在文件之间公平合并。明确的全文总结任务逐段读取全部已提取文本并合并笔记，任何整理失败都明确报错，不以首段冒充全文。

回复保存本轮参考文件、页码和原文片段，界面区分全文、摘录与全文分段整理。压缩和检索存在信息损失，全文分段整理不能代替精确统计工具；模型须保留不确定性，用户可继续追问原文。单轮最多展示 8 处来源，片段最多 1000 字符，以保证最坏 JSON 转义下仍能通过桌面 SSE 帧预算。

## 个人记忆

个人记忆独立于任务摘要，只从用户消息提取明确、稳定的个人偏好或用户要求长期记住的信息。模型返回主题、连续原文和记住/忘记动作；服务端核对逐字原文、敏感内容规则、账号、对话修订、消息活动状态和删除水位后才写入，保存原句作为事实来源。模型推断、助手回答、附件和临时任务不能成为个人记忆。当前自动提取是模型判断加确定性校验，不能承诺零误分类，因此必须保留查看、更正和删除入口。

每账号最多 200 条，注入上下文时按扩展查询的相关词项排序并受独立预算限制。手动条目不被自动整理覆盖。主题更正按源消息时间排序；重复任务不会重复增加版本。明确的记住或忘记请求先完成提取与事务写入，模型只能根据实际处理结果告知是否完成；记忆已提交、后续回复失败时明确提示部分成功，不将整轮都伪装成未执行。普通偏好仍在回复后异步整理。忘记操作不因敏感内容过滤而被拒绝，但自动保存仍执行敏感内容限制。

“参考历史对话”控制同一账号其他聊天的原文召回，不能跨账号或引用非活动分支。关闭该项仍可使用已保存的偏好；关闭“记住我的偏好”同时关闭历史参考与新记忆提取，已有条目保留。当前对话的原文与摘要继续服务当前任务，不因关闭跨对话记忆而丢失。

更新使用乐观版本校验；删除或重命名主题记录水位，清空记录全局水位，用户修改递增 epoch。自动记忆保存所有已使用的消息来源；删除、更正或忘记时排除相关原始轮次的跨对话召回，旧任务不能重建条目。清空后不再自动参考清空前创建的历史消息，原聊天单独保留。用户在当前聊天再次明确提供的信息仍可使用。

助手回复另存扁平化的原文与记忆依赖：依赖被删除、更正、停用或遗忘后，该派生回复也不能参与跨对话召回，避免借助手复述绕过遗忘。沿最近回复继承依赖，不每轮扫描全部历史；依赖超过预算或旧数据缺乏追溯记录时，停用该派生回复的跨对话召回，原始用户消息仍可检索。模型辅助调用结束后再次验证账号、来源修订、活动状态和记忆设置，迟到结果不得进入已变化的上下文。删除源聊天会级联删除由它产生的自动记忆；手动保存的独立条目由用户单独管理。

## 历史版本与运行

已发送消息的附件绑定保持不可变；新附件通过新消息发送。编辑和重新生成保存完整活动路径的不可变消息快照，旧回复通过 active 字段退出当前路径。恢复在事务内归档当前路径并恢复选中快照；用户锁和活跃请求检查防止与生成互相覆盖。快照保留原消息更新时间，恢复操作只更新对话活动时间，不把旧陈述当作新的事实更正。旧快照缺失当时时间时按消息创建时间保守回填。原始消息顺序不重排，账号归属在每个 HTTP 和 Main IPC 边界独立验证。

完成/未完整完成的回复与 pg-boss 整理任务原子提交。独立 OCR worker 进程同时消费 `chat-context-maintenance`，单实例并发 1、任务时限 360 秒，最多重试 3 次；失败保留 24 小时供排查。多个实例的实际并发与连接数须按部署规模核算。后台关闭和原文被删后任务不应回写；后台异常通过 `chat.context_failed` 记录稳定错误摘要，不输出对话内容。先迁移再启动服务，不能仅运行 Web 而省略 worker。

生成总时限 420 秒、桌面传输 450 秒、账号活动请求租约 8 分钟。默认最大输出配置为 65536 token，关闭/低/高/最大档位分别按 16384/32768/65536/131072 收敛到配置上限；推理 token 与正文共用供应商输出预算。应用的正文和推理字符上限仍独立执行。主回复、标题、上下文整理分别记录已知用量；失败或缺失用量保持未知，不能伪造为零。

checkpoint 只能更新当前活动路径中仍在生成的消息；最终保存同时核对生成请求身份与消息状态，终态不能被重复提交或迟到执行覆盖。新请求预留与独立维护任务都会将过期请求及其流式消息在同一事务中收敛到失败，保留已有片段。消息与用量按一致顺序加锁，避免清理和最终保存相互倒置。

用户输入、模型正文与辅助整理结果拒绝 PostgreSQL 无法保存的 NUL 和未配对 UTF-16 代理项，合法 emoji 保持原样。文件解析修复非法字符；字符预算截断不切开代理项对。校验失败不得伪装成保存成功。

历史页返回活动分支 revision；消息、附件与 revision 在同一个 PostgreSQL repeatable-read 只读事务中读取。跨设备编辑或恢复导致 revision 改变时，客户端不合并不同版本的分页或保留旧前缀。每次本地发送、编辑、恢复和账号清理同时使在途读取失效，避免请求结束后迟到的旧页覆盖新回复。恢复期间禁止写入，成功但重新读取失败时明确表达部分成功；其他窗口的生成状态只提供等待反馈，不显示无法执行的本地停止动作。

## 验证边界

隔离数据库集成测试覆盖未登录、来源校验、越权、版本冲突、长回复摘要、尾部原文召回、编辑失效、跨分支恢复、记忆删后防重建、重复任务、关闭与迟到响应，以及原文索引事务、跨对话更正、多来源证据、派生回复遗忘、当地日期边界和格式重试。Responses 协议测试覆盖顺序、响应身份、失败/不完整终态、无终态断流和历史、文件同时出现的 SSE 帧预算。

并发生命周期回归另覆盖账号锁等待隔离、跨账号 requestId 冲突回滚、过期消息收敛、重复终态写入与生成身份不符；上下文测试验证摘要和召回确实重叠执行，以及失败后取消并等待关联任务。HTTP 校验回归确认非法文本在预留额度前被拒绝。这些测试采用隔离数据库和模型替身，不提供真实模型质量或生产吞吐结论。

`VELIN_TEST_DATABASE_URL=... pnpm eval:memory` 是显式调用真实模型的付费验证入口，仅允许名称符合规则的隔离测试库。它创建一次性合成账号与 1200 轮干扰对话，以同范围、相同来源预算的单查询词面检索作为基线，分别记录原文召回、答案检查、降级、耗时及已知 token 用量；结束后清理账号和数据。输出保存在被忽略的 `.review.local/memory-recall/evaluation.json`。用例覆盖换一种说法、跨对话综合、时序、更正、尾部证据、角色区分、恶意引用和缺少依据。答案检查采用固定断言及允许的等价表达，不是完整的语义正确性证明。

这组项目回归不是 LongMemEval 或 LoCoMo 的官方成绩，也没有证明与成熟产品体验相同。查询改写、有限候选和摘要都有召回损失；需持续加入未见场景及真实失败案例，监测质量、费用与延迟，不能由类型检查或一次连通性请求推断。

## 设计依据与取舍

[LongMemEval](https://arxiv.org/html/2410.10813v2)将长时记忆拆成索引、召回和读取，评测信息提取、多会话推理、时间、更正与不知道时的克制；[LoCoMo](https://aclanthology.org/2024.acl-long.747/)用于研究多轮、多会话长期一致性。实现借鉴其保留原文、细粒度召回和时间信息原则，不复制其排行榜数字作为产品保证。

[Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval)强调补充上下文、组合检索与重排，[RRF](https://research.google/pubs/reciprocal-rank-fusion-outperforms-condorcet-and-individual-rank-learning-methods/)提供多路名次合并方法。[Zep](https://arxiv.org/abs/2501.13956)研究时间知识图谱。本项目当前直接复用 PostgreSQL 与已配置模型，避免再引入独立记忆云服务、图库和第二套账号数据存储；保留事实来源、版本和时间约束，接受额外模型调用及查询扩展仍可能失准的取舍。
