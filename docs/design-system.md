# 设计系统

视觉事实来源是 `packages/ui/src/tokens.css` 和 `themes.css`。两个应用从各自 `src/index.css` 导入它们，再按顺序导入本端的功能样式。修改令牌时同时检查桌面与网页；单一载体的布局保持在该应用内。

## 分类与使用

| 类别     | 档位 / 角色                                                               | 应用                                                                          |
| -------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 字体     | `font-sans`、`font-mono`                                                  | 界面与长文使用系统无衬线；代码和授权码使用等宽字体                            |
| 字号     | micro、caption、control、body、input、subtitle、section、page、auth-title | 辅助提示、密集控件、正文、输入、分组与页面标题分别选用；使用 rem 支持字号设置 |
| 字重     | regular、medium、semibold、bold                                           | 正文、操作、分组、页面标题逐级强调                                            |
| 间距     | control-gap、row、section、page；底层 `space-*`                           | 同组控件、字段行、内容分组、页面外围使用不同档位；优先选语义别名              |
| 矩形圆角 | control、compact、field、menu、message、card                              | 按控件与容器角色选档；网页通过 `web-radius-*` 使用较紧凑档位                  |
| 完整曲率 | pill、circle                                                              | 胶囊按钮与圆形按钮；不使用普通矩形圆角冒充胶囊                                |
| 尺寸     | icon-_、control-_、dialog-width-\*                                        | 图形尺寸与命中区分别定义；光学校正只影响槽内墨迹                              |
| 颜色     | canvas、surface、sunken、ink、secondary、border、control                  | 背景、层级、正文、辅助说明、边界与控件，不按“灰色几号”直接选颜色              |
| 动作颜色 | primary / on-primary、blue / on-accent、danger、success                   | 一个区域的主要推进、中性辅助、危险确认与结果状态分别表达；前景与背景成对使用  |
| 动效     | feedback、panel、content、step                                            | 悬停、侧栏、内容、步骤；时间与缓动来自共享令牌                                |

系统主题和显式主题共用同一套色板。桌面原来的 `--text`、`--surface` 等名称仅作为语义别名保留；不能在组件里另造一套深浅色值。网页认证入口保持浅色，账号与安全页面跟随系统。品牌图标的官方颜色、代码高亮主题和主题预览是有明确用途的例外。

## 组件与布局

- `Modal` 使用原生 `dialog.showModal()`：背景不可交互、Tab 在模态内移动、Esc 关闭、关闭后恢复原焦点。首次焦点进入容器；步骤变化重新进入容器，不抢亮输入框。卡片和遮罩仍由本端样式定义。
- `PasswordField` 负责独立的显示/隐藏状态、可访问名称和稳定尾部槽位；认证入口的浮动标签使用 `AuthFields`。
- `cropAvatar` 统一头像裁剪、JPEG 输出和 bitmap 清理；来源尺寸与上传限制来自 contracts。
- 桌面侧栏保留像素宽度偏好，窗口余量由 Grid 分给主区。拖动、收起和临时唤出由 `useSidebar` 管理。
- 网页任务卡使用一个桌面宽度，按窄视口降档；字段区、反馈区与操作区共用骨架。正常步骤切换保持位置，长错误、字体放大或短窗口允许换行与滚动，不能为了锁尺寸隐藏必要内容。
- 登录与注册共用字段 DOM；验证码只在用户点击发送后投递。推进按钮按有效输入启用，表单使用 `noValidate`，错误反馈提供 `role="alert"`。
- 普通页面编辑、验证卡片和头像裁剪是不同的布局类型；统一它们的标尺与原语，不强行使用同一种排布。

## 样式维护

`src/styles` 按窗口、认证、对话、设置与响应式规则拆分；`apps/auth-web/src/styles` 按认证、账号、安全、对话框与动效拆分。入口中的导入顺序保留原有级联，调整顺序属于行为变化。

新增视觉值先检查已有角色。确需新增时，在令牌层说明用途；不要用反复追加覆盖选择器解决基础分类错误。像素用于固定命中区、边框和光学校正，rem 用于文字，弹性单位用于内容与窗口适配。

验证至少覆盖登录/注册共有字段的位置、450/335/290 卡片档位、长错误、键盘焦点、深色主题和 reduced motion。布局预算只是默认值，实际内容可读性优先。
