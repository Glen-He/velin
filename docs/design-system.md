# 设计系统

视觉事实来源是 `packages/ui/src/tokens.css` 和 `themes.css`。两个应用从各自 `src/index.css` 导入它们，再按顺序导入本端的功能样式。修改令牌时同时检查桌面与网页；单一载体的布局保持在该应用内。

## 分类与使用

| 类别     | 档位 / 角色                                                                       | 应用                                                                          |
| -------- | --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 字体     | `font-sans`、`font-mono`                                                          | 界面与长文使用系统无衬线；代码和授权码使用等宽字体                            |
| 字号     | micro、caption、control、body、input、subtitle、section、page、auth-title         | 辅助提示、密集控件、正文、输入、分组与页面标题分别选用；使用 rem 支持字号设置 |
| 字重     | regular、medium、semibold、bold                                                   | 正文、操作、分组、页面标题逐级强调                                            |
| 间距     | control-gap、row、section、page；底层 `space-*`                                   | 同组控件、字段行、内容分组、页面外围使用不同档位；优先选语义别名              |
| 矩形圆角 | control、compact、field、menu、message、card                                      | 按控件与容器角色选档；客户端连续曲率与网页圆弧分别定标                        |
| 完整曲率 | pill、circle                                                                      | 胶囊按钮与圆形按钮；不使用普通矩形圆角冒充胶囊                                |
| 尺寸     | icon-_、control-_、dialog-width-\*                                                | 图形尺寸与命中区分别定义；光学校正只影响槽内墨迹                              |
| 颜色     | canvas、surface、sunken、ink、secondary、border、control                          | 背景、层级、正文、辅助说明、边界与控件，不按“灰色几号”直接选颜色              |
| 动作颜色 | primary / on-primary、accent-fill / on-accent、danger-text / danger-fill、success | 文字、图标、焦点与填充分别选色；前景与背景成对使用，不以相同色值代替相同语义  |
| 动效     | feedback、panel、content、step、overlay                                           | 悬停、侧栏、内容、步骤；时间与缓动来自共享令牌                                |

客户端自绘矩形使用 `corner-shape: squircle`，半径与曲率在对应组件样式内一起声明，不维护易漏项的全局选择器名单。圆形与胶囊明确保持 `round`；原生窗口圆角交给 AppKit。聊天输入框保留已确认的固定圆弧端帽，多行增长不改变端帽形状。

网页使用普通圆弧和独立 `web-radius-*` 档位；相同数值在两种曲率下观感不同，不直接引用客户端半径。共享视图通过 `surface-radius-*` 与 `surface-corner-shape` 获取载体配置。两端保持相同角色、层级和密度，再比较真实控件轮廓；数值是产品校准，不能宣称是 Apple 官方像素标准。嵌套矩形按内缩协调内外曲线；重叠于同一边界的预览层继承父圆角，不各写一档。

系统主题和显式主题共用同一套色板。同一主题下，客户端与网页使用相同语义配色；网页跟随系统，客户端可按偏好显式选择主题。桌面原来的 `--text`、`--surface` 等名称仅作为语义别名保留；不能在组件里另造一套深浅色值。品牌图标的官方颜色、代码高亮主题和主题预览是有明确用途的例外。

`color-icon-muted` 只用于图标，辅助文字使用 `color-secondary`；`color-blue` 用于焦点和图形，链接使用 `color-blue-text`，白字实体填充与选中状态使用 `color-accent-fill`。危险提示使用 `color-danger-text`，白字最终确认使用 `color-danger-fill`。中性、链接与普通主操作文字按实际背景检查至少 4.5:1；常态危险色按已确认的 Apple 默认鲜艳红显示，增强对比度模式再满足 4.5:1 配对，见 `packages/ui/tests/design-contrast.test.ts`；语义按钮、滚动和布局细则见 [界面约束](interface-guidelines.md)，选择依据见 [工程与设计维护规范](engineering-guidelines.md)。

## 组件与布局

页面卡片没有独立定宽：先选择内容列，再让同列的标题、分组、身份卡和列表卡共享左右边线。列宽与弹窗宽度均为上限，实际宽度受父容器和安全留白限制。

| 布局角色              | 事实来源                                                                                  | 使用范围                                                             |
| --------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 认证列                | `layout-auth-max-width`                                                                   | 桌面与网页共用字段空间预算；载体只决定外围布局                       |
| 桌面设置列            | `layout-settings-card-max-width` / `layout-settings-gutter` / `layout-settings-max-width` | 卡片上限加外围留白推导外框；内缩相对自身容器计算                     |
| 网页账号列            | `layout-account-max-width`                                                                | 引用同类设置卡片上限，账号、安全、设备、通行密钥共用边线，留白在列外 |
| 阅读列                | `layout-reading-max-width`                                                                | 聊天正文、错误、空状态与输入框共同对齐，随字号自然伸缩               |
| 单字段编辑 / 简短确认 | `dialog-width-edit`                                                                       | 两端名称编辑与简短确认弹窗                                           |
| 操作任务              | `dialog-width-task`                                                                       | 验证任务与两端头像编辑；正文引用认证列预算，加内缩推导外框           |
| 多行列表              | `dialog-width-list`                                                                       | 桌面设备列表；内容增多时滚动，不按条数加宽                           |
| 裁剪区域              | `layout-avatar-crop-max-width`                                                            | 两端图片预览与缩放区域同步收缩                                       |

宽度选择依据与取舍见 [布局取舍](engineering-guidelines.md#布局取舍)。不使用无真实调用方的备用宽度档位。断点由需要改变排布的内容决定：桌面富控件使用设置列的 container query；网页弹窗按可用视口统一降档。普通紧凑行继续单行省略，主题预览等富控件可以改为上下排布，操作与表单错误不能被裁切。

- `Modal` 使用原生 `dialog.showModal()`：背景不可交互、Tab 在模态内移动、Esc 关闭、关闭后恢复原焦点。首次焦点进入容器；步骤变化重新进入容器，不抢亮输入框。共同业务卡片复用共享视图；载体差异由角色令牌提供。
- `TruncatedText` 用于账号、设置、设备、凭据和侧栏列表的紧凑文字：每条文字保持单行，超宽时显示省略号，不播放滚动动画、不撑高面板；DOM 与悬停提示保留完整文字。聊天正文、表单反馈与完整任务说明仍按其内容类型排版。
- `PasswordField` 负责独立的显示/隐藏状态、可访问名称和稳定尾部槽位；认证入口的浮动标签使用 `AuthFields`。
- `ConfirmationDialog`、`DisplayNameDialog`、`AvatarDialog` 共用标题、字段、反馈与动作区。确认失败留在原卡片，可直接重试；关闭后的旧响应不操作新卡片。两端仅提供所属网络或 IPC 边界。
- `cropAvatar` 统一头像裁剪、JPEG 输出和 bitmap 清理；来源尺寸与上传限制来自 contracts。
- 桌面侧栏保留像素宽度偏好，窗口余量由 Grid 分给主区。拖动、收起和临时唤出由 `useSidebar` 管理。
- 网页任务卡由正文预算与内缩推导宽度，按窄视口连续收缩；字段区、反馈区与操作区共用骨架。正常步骤切换保持位置，长错误、字体放大或短窗口允许换行与滚动，不能为了锁尺寸隐藏必要内容。
- 登录与注册共用字段 DOM；验证码只在用户点击发送后投递。推进按钮按有效输入启用，表单使用 `noValidate`，错误反馈提供 `role="alert"`。
- 普通页面编辑、验证卡片和头像裁剪是不同的布局类型；统一它们的标尺与原语，不强行使用同一种排布。

## 按钮、线条与稳定几何

按钮、面板和文字动作的事实分别位于 `Button.tsx` / `button.css`、`Panel.tsx` / `panel.css`、`text-action.css`，不能在应用侧复制旧变体。`buttonWidthTier` 决定标签档位，`ActionGroup` 共用最长稳定标签档；具体角色见界面约束。桌面默认紧凑按钮使用 caption 字号和 compact 高度，认证全宽提交使用 body 字号和 regular 高度；粗指针以 touch-target 为下限。图标命中区与墨迹分别选档。

以下是默认 16px 根字号下由上述令牌推导的尺寸示例，修改以源码为准，放大字号随公式增长：

| 标签档 | 紧凑按钮宽度（两端） | 认证常规按钮宽度（两端） |
| ------ | -------------------- | ------------------------ |
| 2 字   | 64px                 | 68px                     |
| 4 字   | 88px                 | 96px                     |
| 6 字   | 112px                | 124px                    |
| 8 字   | 136px                | 152px                    |

默认紧凑高 32px、常规高 42px；粗指针高至少 44px，按钮文字使用 body 档。全宽角色直接占满列；同组任意数量的按钮使用同一尺寸角色与最长档，不混用 compact / regular。

面板外框、行分割线和控件边框分别引用 `line-width-panel`、`line-width-divider`、`line-width-control`，当前采用相同线宽；不保留一端半像素、另一端一像素的重复体系。普通紧凑面板外高按 `N × panel-row-height + (N − 1) × line-width-divider + 2 × line-width-panel` 推导。分割线单独占位，左右内缩跟随行内容起点。行使用 min-height；放大文字、富控件或错误反馈超出预算时自然增长，不隐藏内容。密度、内缩、头像与字号角色两端共用，外围导航可按载体不同。

## 动效分类

`motion.css` 提供两端共用的动画，时长、距离和缓动引用 motion 令牌。

- 局部反馈：悬停、按下、选中等短反馈，只改变对应颜色或状态，不推移文字和布局。
- 内容切换：同级设置内容或页面进入采用短淡入；窗口 resize 不播放布局动画。
- 流程步骤：前进从右进入、返回从左进入，两端使用相同距离与节奏；方向随实际步骤历史更新。客户端保持稳定轨道，网页支持时使用 View Transitions，较旧浏览器仍可即时切换。
- 弹层：遮罩淡入，卡片轻量位移与缩放入场；只在打开时播放，内部加载和步骤不重新播放外壳动画。
- 直接操作：拖动滑块、裁剪和侧栏分隔线直接跟随指针，不加延迟；侧栏开合使用独立 panel 档。
- 运行状态：加载旋转与生成状态有独立持续反馈；reduced motion 禁用位移和持续动画，状态文字仍可读。

动画说明来源、去向或结果，不为了「有动画」给每个输入字段添加动效。载体能力不足时优先保留客户端体验，网页以可用的交互和即时状态作为退化路径。

## 样式维护

`apps/desktop/src/renderer/styles` 按窗口、认证、对话、设置与响应式规则拆分；`apps/web/src/styles` 按认证、账号、安全、对话框与动效拆分。入口中的导入顺序保留原有级联，调整顺序属于行为变化。

新增视觉值先检查已有角色。确需新增时，在令牌层说明用途；不要用反复追加覆盖选择器解决基础分类错误。像素用于控件、边框和稳定几何；rem 用于文字和按字号约束行长的阅读列；弹性单位用于内容与窗口适配。

验证至少覆盖登录/注册共有字段的位置、完整与受限空间下的任务卡片、长错误、键盘焦点、深色主题和 reduced motion。布局预算只是默认值，实际内容可读性优先。
